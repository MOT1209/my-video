1) الخلاصة التنفيذية

التطبيق سليم تقنياً وقريب من قابلية النشر. كل فحوص الصحة الأساسية نجحت: بناء الإنتاج نظيف، TypeScript بلا أي خطأ، ESLint بلا أي ملاحظة، والاختبارات 143 من 144 ناجحة (عنصر واحد فقط فشل بمهلة تحت التشغيل المتسلسل، ويجتاز منفرداً). السياسة الأمنية تقوم على الإغلاق الاستباقي (fail-closed): في الإنتاج، غياب Upstash أو Clerk أو DATABASE_URL يغلق المسارات المكلفة استباقاً بدل تشغيلها متكلفة بصمت.

الفجوات المتبقية ليست في الكود بل في الجاهزية التشغيلية: تهيئة مفاتيح Clerk/Neon/Upstash فعلياً، تنفيذ هجرات قاعدة البيانات، جولة دخان حية قبل الإطلاق، معايرة أسعار حزم الكريدت مقابل تكلفة التصيير المقاسة، وسياسة الاحتفاظ والتخليص للفيديوهات والـ snapshots.

3) البنية الحالية

الواجهةShortsEditor.tsx: محرر الخطاف/المشاهد/الصوت/الكابشن/الثيم + useEditorState لحفظ الحالة محلياً بمفتاح my-video:editor:v1 بعد debounce 300ms، ولوحة حسابات أعلى المحرر.
الفيديوRemotion 4.0.538 — ShortMain بخمس ثيمات، WordCaptions بالكابشن كلمة-بكلمة عبر createTikTokStyleCaptions وspring بأربعة أنماط (pop/karaoke/slide-up/glow)، Background بـ Ken Burns وإمكانية خلفية فيديو + طبقات تعتيم وحبيبات + خلفيات AI.
الصوتEdge-TTS مجاني مع مشتقات كلمة-بكلمة عبر أحداث WordBoundary + بديل رسمي عبر Azure Speech عند فشل Edge بصرياً برسالة واضحة. المخاطرة الأولى في الخطة (انكسار Edge بلا بديل) مُغلقة فعلياً.
التصييرVercel Sandbox + snapshot cache + كاش ناتج حتمي بمفتاح sha256 + قياس $/video من Active CPU/Memory/Network + SSE للتقدم + قفل موزّع ذري يفك تماماً لمالكه الحقيقي.
SaaSClerk + Neon/Drizzle + Stripe checkout وwebhook بتوقيع مُتحقق، نظام كريدت (تصيير = 1، ترحيب = 3، حزم 10/$5 و30/$12 و100/$35)، خصم بعد التأكد من غياب الكاش واسترجاع عند الفشل، حفظ/تحميل/حذف المشاريع.
تحجيم الحمايةUpstash Redis موزَّع (‎20 طلب/5 دقائق لـ TTS، 5 عمليات/ساعة لـ Render)؛ فشله يغلق المسارات المكلفة بـ 503 مع رسالة عربية وRetry-After بدل تشغيلها بلا حد. خارج الإنتاج يعمل بديل في الذاكرة.

4) نقاط القوة

  • أمن استباقي حقيقي: استخراج مقالات يرفض العناوين الخاصة/المحجوزة والـ DNS الداخلي، يثبت الاتصال على العنوان المُحلَّل، يمنع الـ redirect، ويحدّ المهلة والجسم بعشرة ثوانٍ و2MiB (حماية SSRF فعّالة). الـ webhook بلا توقيع يُرفض مباشرة.
  • طبقات تخزين مؤقت ثلاثية: كاش ناتج التصيير + كاش الصوت بمفتاح voiceId::text + كاش صور AI بمفتاح content-hash — الفيديو نفسه لا يُصيَّر مرتين، والتوليد نفسه لا يُدفع مرتين.
  • جودة اختبار عالية: 144 اختباراً تغطي عناصر دقيقة: توكن Sec-MS-Gec، القفل الموزّع، حالة فشل Redis، المراجعة الكاملة للكود، الأسعار، والطابور.
  • السلوك بلا مفاتيح محكوم: كل مسار بلا مفتاح إنتاجي يرد برسالة عربية إرشادية ورقم خطأ صحيح، بلا انهيار أو تشغيل بلا حماية.
  • التعارف مع Vercel: Cron وBlob وSpend Management وSandbox متكاملة حول مسار التصيير.

5) خطة الإصلاح — بالأولوية

P1 — استقرار مصادقة الاختبار (ساعة عمل) أولوية عالية

اختبار المصادقة يجتاز منفرداً وينتهي بمهلة تحت التشغيل المتسلسل، لأن الـ mock ينفّذ مكالمة Clerk على الشبكة التي قد تتجاوز المهلة الافتراضية في Bun (5 ثوانٍ). الزمن الفعلي 1.1 ثانية عند النجاح و5.4 ثانية عند احتكاك الشبكة.

  • إضافة حد مهلة صريح لمكالمة Clerk في src/lib/auth.ts (عبر AbortSignal أو Promise.race) ليرد 503 سريعاً بدل تعليق المسار.
  • في الاختبار، رفع مهلة تشغيله عبر .timeout الموفرة في Bun.
  • المعيار: bun test --max-concurrency=1 src/lib types ينجح 144 بلا أي فشل متكرر.

P2 — نظافة المستودع (15–30 دقيقة) أولوية متوسطة

  • bash.exe.stackdump غير متتبع — حذفه وإضافة *.stackdump إلى .gitignore.
  • مجلد بالاسم العربي «نعم الايجلمهارات و ادوات تعليم/» بداخله gemini.txt — ليس كوداً ولا وثيقة تقنية. إما نقله إلى notes/ وترتيبه، أو حذفه بقرار مالك المستودع.
  • plan.md آخر تحديثه 2026-10-19 بينما المراحل 1–4 فيها منجزة — تحديث سجل التقدّم بالنتائج المقاسة أعلاه وربطه بالتقرير الحالي.
  • تقريران متنافسان في الجذر (report.html وcode-review-report.html) — توحيدهما تحت docs/audits/ مع الإبقاء على رابط واحد في README.md.

P3 — فجوات المنتج (2–4 أيام عمل) تحسينات

  • سياسات البيانات: أساس أي SaaS — صفحة «حذف الحساب ومشروعاته» وتصدير بياناته وقاعدة احتفاظ (مثلاً 90 يوماً)، وتفعيل cleanup-blobs كروتيناً دورياً لا سكربتاً يدوياً.
  • معايرة الأسعار: render-metrics.ts يقيس $/video الفعلي، لكن حزم الكريدت (10/$5…) وُضعت تقديرياً ولا علاقة لها بالقياس. اربط قيمة الكريدت بالتكلفة المتوسطة في أول أسبوع تشغيل.
  • تميّز الاشتراكات: الخطة أوضح أن المنافسين لا يبيعون اشتراكات — خطة شهرية بـ«كريدت أعلى» فوق نمط الكريدت الحالي (بعد التشغيل) تمنح نقطة تميّز يحسّنها العملاء.
  • قوالب جاهزة: مكتبة قوالب (خطافات + CTA + أنماط كابشن مثبتة) بست قوالب فأكثر — أكبر رافعة للاحتفاظ بالمستخدمين بتقليل الزمن حتى أول فيديو ناجح.

8) منهجية المراجعة

المراجعة اعتمدت على قياس فعلي لا على استكمال تقارير قديمة: شغّلنا tsc وeslint وbun test وnpm run build على هذا الفرع بالضبط وسُجّلت مخرجاتها. وفُحصت البنية من واقع الملفات الموجودة (14 مسار API و102 ملف TypeScript). أعلناً كل فشل أو فحصاً لم نستطع إتمامه بدل التصريح بأنه نجح.
