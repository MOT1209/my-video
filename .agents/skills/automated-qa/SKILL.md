# Automated Testing & QA

حين يضيف الوكيل سلوكاً أو يصلح خللاً، اتبع هذا الـ skill. العدّاء الرسمي الوحيد: `bun test` (أمر `npm test` يستدعيه).

## الوضع الحالي

- الاختبارات: `types/shorts.test.ts`، `src/lib/sec-ms-gec.test.ts`، `src/lib/sandbox-session.test.ts`، `src/lib/render-cache.test.ts` (+ جديد في الشجرة)، `src/lib/render-metrics.test.ts` (+ جديد)، `.agents/skills/*/​*.test.ts` (Groq/Fish بلا شبكة).
- لا Playwright ولا اختبار متصفح بعد (`.gitignore` يستبعد `.playwright-mcp/` فقط). أي E2E يُقيَّم أولاً (انظر أدناه).

## متى يُفعَّل

- أي منطق جديد/مُصلح: وحدة + تكامل API + schema + JSON مشوه + فشل TTS + توقيت كابشن + عربي/RTL + فشل render + صحة كاش + حدود معدل.

## سير العمل

1. اكتب/حدّث الاختبار **أولاً** للسلوك الجديد (TDD حيث أمكن): مدخل → توقع → حالة حدّية.
2. افصل الوحدة (خالصة، بلا شبكة) عن التكامل (API/SSE بحدود مزيّفة) عن الشبكة الحقيقية (معزولة خلف بيئة، لا تعمل في CI).
3. كل إصلاح خلل = اختبار انحدار يعيد إنتاجه قبل الإصلاح ويفشل بدونه.
4. شغّل `bun test` كاملاً قبل الادعاء. سجّل العدد الفعلي (ناجح/فاشل). لا تقل "نجح" دون تشغيل.

## ما يجب تغطيته (قائمة التحقق)

- [ ] وحدة: `buildNarrationText`، `distributeCaptionsEvenly` (فارغ/صفر مدة → `[]`)، `getShortDurationInFrames` (سقف 60 + ذيل 1s)، `hashNarration` (حتمي + تمييز الصوت)، `stableStringify` (ترتيب + تجاهل `undefined`)، `renderCachePath` (48 حرفاً)، `estimateRenderCostUsd` (قيم مرجعية).
- [ ] عقود: `ShortProps` (رفض 13 مشهداً/نص 281/hook 121/captions 601)، `BackgroundMedia` (رفض `zoomTo>1.4`/`dim>0.9`/URL سيئ)، توافق خلفي (طلب قديم ينجح).
- [ ] API: JSON مشوه → 400 لا 500؛ TTS فشل مزود → خطأ عربي لا تسرب؛ render فشل sandbox → حدث `error` + إغلاق الدفق + تسجيل خسارة (`finally`).
- [ ] كابشن/عربي: تحويل ثوانٍ→ms، صفحات `combineMs`، كاريوكي RTL ‏270deg مقابل LTR ‏90deg، سطر طويل لا يفيض، `fitText` مرة/صفحة.
- [ ] كاش: نفس التكوين = نفس المسار؛ طلبان متكافئان بترتيب مفاتيح مختلف = نفس الهاش؛ `head()` فشل غير "غير موجود" = تعطيل كاش لا كسر render.
- [ ] حدود: TTS ‏20/5min وrender ‏5/hour (مسموح→مرفوض + `Retry-After` + إعادة ضبط النافذة).

## Playwright (تقييم صريح قبل الاعتماد)

- اعتمده فقط لفجوات لا يغطيها `bun test`: تدفق المحرر، RTL مرئي، تحقق نماذج، سلوك preview، معالجة فشل API في المتصفح.
- شروط: متصفحات مثبتة في CI، لا خدمات خارجية غير مضبوطة (سيفشل الرقائقي)، مهلات صريحة، لقطات عند الفشل فقط. ابدأ بـ ≤5 سيناريوهات حرجة.
- ممنوع اختبارات تعتمد على Blob/Sandbox/TTS حقيقي دون بيئة مضبوطة.

## المعايير والممنوعات

- لا اختبارات تعتمد على API مدفوعة/إنتاجية في CI. لا `sleep` ثابت — انتظر شروطاً.
- لا كتم فشل (`try/catch` يبتلع) في الاختبارات. الفشل يُبلَّغ بدقة (الملف:السطر + المدخل + المتوقع/الفعلي).
- لا نسخ اختبارات مكررة عبر المزودين — ضع المشترك في `ai-voice-tts` وأعد استخدامه.

## معايير القبول

- كل سلوك جديد له تغطية انحدار ذات معنى تعمل في CI.
- `bun test` أخضر قبل الدمج. أي تخطٍّ موثق بسبب (شبكة/بيئة) لا صامت.

## التوثيق

- اذكر في وصف التغيير: ما اختُبر، ما لم يُختبر ولماذا، وكيف يُشغَّل (`bun test` + أي متغير بيئة للاختبارات المعزولة).
